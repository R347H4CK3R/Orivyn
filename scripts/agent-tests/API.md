# Local read-only task core contract

`LocalAgentCore.js` exposes frozen global `OrivynLocalAgent` in a bare JavaScript context and guarded CommonJS export for tests. It uses no browser APIs, Node APIs, eval, network, timers or filesystem. Every operation is synchronous. Invalid inputs throw; callers must handle the exception without dispatching a tool.

- `create(goal, uuid)` → serialized state. Goal max512UTF8bytes; UUID normalized lowercase.
- `acceptDecision(stateJSON, modelText)` → state. Strict JSON, no fences, duplicate keys or extra permission fields. An external read-only tool decision produces `status=running` and `pending={operationID,name,arguments}` BEFORE dispatch.
- `recordResult(stateJSON, resultJSON)` accepts exact `{operationID,result}` with bounded plain-text result; stale/duplicate results reject.
- `recover(stateJSON)` changes running→interrupted without executing anything; a ready legacy task whose complete evidence exceeds the prompt budget becomes failed with preserved history.
- `resume(stateJSON)` requires interrupted, archives the abandoned pending operation and returns ready; it does not replay that operation.
- `cancel(stateJSON)` and `fail(stateJSON,message)` persist clear terminal outcomes. Cancel is idempotent only when already cancelled; answered tasks cannot be overwritten through either API.
- `prompt(stateJSON)` requires ready and returns a self-contained prompt of at most 3,500 UTF-8 bytes. `UNTRUSTED_RESULTS_JSON` contains every successful result in full, with its step, tool name and actual arguments. `RESULT_VIEW_JSON` retains validated legacy cursor metadata, without duplicating page text. Earlier model calls have no retained memory. No evidence is silently truncated or discarded to fit.
- A new result that makes complete evidence too large is preserved in history, then the task becomes failed with an explicit request to start a narrower task. Resume, ready-state recovery, decision acceptance and prompt generation independently enforce this bound. An existing running pending marker remains until its actual result arrives or the user explicitly resumes/cancels abandoned work.

State fields: version,id,goal,status,revision,steps,history,pending,answer,error,internalReads,resultView,exposedThrough. States:ready/running/interrupted/answered/failed/cancelled. At most6tool calls; a final answer is still allowed after the sixth result. An answer requires at least one succeeded local tool result; interrupted-only history is insufficient. Answered still means model prose only, not proof of semantic faithfulness or any external action.

Allowed read-only tools:
- get_app_info: arguments{}
- list_models: arguments{}
- search_conversations: arguments{query:string up to256UTF8bytes,limit:integer1…10}
- read_result: arguments{step:integer1…6,offset:integer0…4096}; reads an existing succeeded stored result only. Handled internally by the reducer: returns ready with no pending operation, increments internalReads/revision but not steps. Native must persist and continue its model loop WITHOUT dispatch or recordResult. Maximum 102 internal cursor reads is independent of six external calls. Cursor movement never substitutes for simultaneous model context. All successful results must fit together before any further decision; an extra cursor read fails the task, while answering/cancelling at the limit remains available for a fitting context.

Model decision shapes: `{type:"tool",name,arguments}` or `{type:"answer",text}`. Native tools and provider invocation remain outside this core. Native MUST save running state before dispatch and serialize updates using task ID/revision. A pure reducer cannot prevent replay of an old valid snapshot or authenticate disk contents. Do not accept stateJSON from the model or a tool result.

Bounds: state65536UTF8bytes; decision/result envelopes32768bytes; result/answer4096bytes; error512bytes; JSON depth12; arrays32items. Strict string validation rejects lone surrogates. Complete prompt JSON escaping and UTF-8 bytes are measured against 3,500 bytes; overflow fails closed with all evidence retained. This is separate from the engine’s unchanged real-tokenizer context limit. Source API supports Unicode within byte bounds.

Evidence: the full JavaScript regression suite passes with complete-context, overflow, hostile fields, cursor bounds and legacy-state coverage. Portable Swift storage/dispatcher checks are separate from actual model quality and Apple execution. See the current workflow evidence documentation; no successful task follows merely from reducer tests.

Paging state: internalReads defaults0; resultView is null or {step,offset}. Newly recorded result selects its first page. Legacy snapshots missing BOTH fields migrate to0 reads and latest succeeded result at0; partial or malformed paging state rejects. Migration validates the old snapshot and increments revision once, making changed serialized bytes acceptable to native CAS persistence. Recover a legacy running state adds a second revision for interruption. Re-reading migrated state does not increment again. Always recover/persist before model inference; prompt returns text rather than a migrated snapshot. Internal tools cannot appear as pending or history operations. Revision maximum160 accommodates bounded paging and recovery. All stored results remain capped at 4,096 bytes; the full prompt may require an earlier stop. `exposedThrough` remains validated for compatibility but no longer advances or authorizes an answer. Old terminal answers are not retroactively regenerated or revalidated. Source-result truncation flags still apply; complete returned evidence is not a complete original library.

Native grammar integration remains unchanged: initial root permits external tools, later root may also emit a bounded read_result cursor or answer. The reducer and native dispatcher retain their independent provenance checks. Actual read_conversation calls still require a successful search returning that conversation ID; prompt changes do not grant authority.

Conversation search includes titles, messages and stored attachment names/extracted text without opening original files. New results carry evidenceSource: title, message, attachment_name or attachment_text. These are provenance labels, not fact or OCR verification. Verified-plan recovery accepts old results without the optional label and rejects unknown labels/extra keys.
