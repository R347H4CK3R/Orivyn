# Design and testing: review repair round 1

**Status: implementation repaired for independent re-review, not native-validated or integrated.** Only this isolated Office workspace was changed. Main candidate, AppModel, Conversation, active configuration, current app tests/scripts, CI and repositories were not modified. The existing integration diff remains a proposal.

## Review fixes

- **I1:** All formats render incrementally into one finite sink. No XLSX/CSV row string array, joined row, or complete escaped shared-string copy is constructed. Labels, separators, annotations and escape expansion count toward **240,000 rendered UTF-8 bytes** and **60,000 rendered Unicode scalars**, the latter a conservative bound on Swift Characters. Overflow seals the sink, preserving a prefix. After saturation all bounded input/cell validation continues, but repeated values are not rendered. Custom format metadata also shares raw String storage rather than interpolating one large format label per style. Native tests cover a 61,550-byte XLSX with 10,000 references to one 32-KiB string (the former path implied 327,680,000 repeated value bytes), combining marks, escapes, every supported format, and memory/time metrics.
- **I2:** Every numeric cell resolves explicit `s` or default index 0. Date/custom styles therefore behave identically for omitted and explicit `s="0"`. Row/column inherited formatting is deliberately not guessed. Its metadata is validated; affected omitted-cell numeric values and frontloaded notes say the inherited format is unresolved. Explicit cell styles still apply.
- **I3:** Formula array/shared/data-table result rectangles are collected before output. Followers with stored values are labeled cached; present follower cells without caches are labeled unavailable. Nothing is evaluated or filled into absent cells. Caps: **256 sparse rectangles per worksheet**, **1,000,000 cells per rectangle**, **1,000,000 total potential range-overlap/cell-membership comparisons across the workbook**. Coordinates, anchors, ordering and overlapping ranges are validated; no range is enumerated or converted into a dense grid. Unsupported/malformed/excessive range metadata fails honestly.
- **I4:** Named attack fixtures now reach named error stages: entry bytes, total bytes, expansion ratio, overlapping data intervals, actual streamed size and CRC integrity. The bomb uses an inert `.dat` name. The overlap fixture has mutually consistent local/central records and a valid embedded local header; it reaches the interval gate. XCTest asserts exact `OfficeValidationStage` cases. Deterministic native cancellation tests cancel the actual current Task at decompression/cell checkpoints, after private staging and during importer extraction, and assert staged-copy cleanup. These are prepared tests, not executed evidence.
- **M1:** File open adds `O_NONBLOCK` before same-handle fstat. The FIFO test keeps a guard writer open so even a regressed blocking implementation cannot hang the test runner; static checks also require the nonblocking flag.
- **M2:** UTF-8 declaration detection examines only a bounded actual XML declaration through `?>`, with XML whitespace and quote grammar for its encoding attribute. XMLParser still validates full grammar. Legal spacing, no-encoding declarations with later `encoding` content, and misleading comments are fixtures.
- **M3:** Defined Deflate level bits are accepted only for Deflate. A bounded empty Deflate stream is permitted and must produce exactly zero bytes and CRC zero. Unknown/encryption flags and zero-input Deflate streams remain rejected. Empty-callback/progress limits remain in place.
- **M4:** Only `word/printerSettings/printerSettings[0-9]+.bin` and the corresponding `xl/` names get an inert-part exception. Their real bytes and CRC are bounded/checked, never interpreted. Notes disclose ignored printer settings. VBA/ActiveX/OLE embedding names remain rejected. Other unknown binary parts produce an honest unsupported-part error and text/CSV/simplified-copy workaround. The printer fixture is synthetic, not a claim of native printer-settings interoperability.

## Existing safety boundary preserved

Official MIT ZIPFoundation **0.9.20**, immutable commit **22787ffb59de99e5dc1fbfe80b19c97a904ad48d**, performs decompression. The strict ZIP32 gate is metadata validation, not a home-grown compression codec. Every entry is streamed, including ignored parts. No filesystem archive extraction, document upload, network runtime, process execution or formula execution exists.

Input is a user-selected regular local file/private staged snapshot, at most 10 MiB, opened with O_NOFOLLOW/O_NONBLOCK and fstat on the same handle. ZIP limits remain 512 entries, 4 MiB per expanded part, 32 MiB total and 200:1 per-entry expansion, with exact observed size and CRC checks. XML still rejects DTD/entities, disables external resolution and bounds per-part depth 64, nodes 80,000, text 2 MiB, attributes 32 and string bytes 32 KiB. Shared strings are capped at 20,000 and worksheets at 32. Output rows/cells remain capped at 1,000/10,000 across sheets.

Relationships resolve only to package dictionary keys. Canonical contained parent references and rooted OPC part URIs are supported; OS/archive absolute paths, traversal outside the package, URI ambiguity and missing targets fail. External hyperlinks are omitted; other external relationships fail. DOCX is body text/tables only. XLSX keeps raw numbers, typed values, serials/1900 or 1904 epochs, custom-format annotations and clearly labeled stored caches. CSV/TSV is strict UTF-8 quoted data. Images/scanned pages, exact layout, Office execution, old DOC/XLS, macro-enabled and unusual unsupported profiles remain outside scope.
