# Reviewed plugin connections and tool calls

Orivyn installs connection metadata, never downloaded iOS code. Free local chat stays independent; external servers may have their own account, network and compute costs. The first concrete plugin workflow is: enter a user-chosen HTTPS MCP endpoint and optional token, explicitly connect to retrieve a bounded catalog, review server identity and tools, save the connection, explicitly choose a tool, enter arguments, review the exact destination/tool/arguments, then run once. A result is remote data, not authority to run another tool. The model never receives the credential, and no conversation/attachment/memory is implicitly sent.

Alternatives: arbitrary downloaded native plugins violate iOS's executable/sandbox model; an unbounded tool-agent loop trusts small-model output too much; a proprietary hosted backend violates the free-first expectation. A bounded MCP client and permission broker use real user-controlled servers without inventing a virtual computer. Initial support is the exact version/subset in `2026-11-12-mcp-client-design.md`. It does not imply full MCP compatibility or that a provider has been tested.

Connection metadata is local, bounded to eight endpoints. Secrets are optionally saved only after a separate explicit Remember token choice, in a separate ThisDeviceOnly Keychain namespace. Without that choice they live in memory until disconnect/background. Never log token, session, arguments or returned content. No automatic reconnect on launch. User can disconnect and remove a saved connection. Removal must not delete remote data or claim token revocation on the server. Metadata load failure preserves existing bytes and disables writes rather than resetting data.

One preparation or execution at a time. A connection operation has an owner UUID; cancel/background invalidates it before awaiting cancellation/close, so late callbacks cannot restore a session. Successful discovery produces a staged connection, not a persistent install. Saving metadata is explicit. Each reviewed call captures a fresh UUID, connection UUID, catalog revision, exact tool name, immutable validated JSON arguments and creation time. Execution consumes that review exactly once, requires the same live session/catalog and foreground, and expires after five minutes. Editing arguments, selecting another connection/tool, rediscovery, disconnect and background invalidate review. Tool annotations do not skip review. Dangerous data/financial/security/legal operations require their specific human action or approval; a connector cannot turn a suggested tool name into unrestricted authority.

Before dispatch, atomically persist a bounded execution record (ID, timestamp, connection ID, sanitized display title, tool name, state). If persistence fails, do not call. Immediately mark dispatched work running; app restart changes interrupted running entries to outcome unknown and never replays them. On reply distinguish server-reported completion, server-reported tool error, definite local failure before dispatch, and uncertain outcome. Cancellation/timeout after sending may already have acted, so never show a false 'undone' or automatically retry. Returned text/images/structured values are shown as inert remote data, separately from Jarvis answers. No hidden HTTP image fetching. Cap records at 100, keep arguments/results out of durable logs by default, and keep at most one bounded result in memory.

UI belongs in Plugins: Add connection, Saved connections, live discovered tools, and execution log. Missing endpoint is a real configuration boundary, not a fake connected state. A dedicated computer connection can later use the same broker with an independently authorized workspace-limited companion. A remote browser is not a whole desktop; no host-wide shell, shared browser cookies, secret harvesting or elevation is added implicitly. Broader autonomous planning, approved multi-step workflows, companion isolation and UI-led task resume are separate acceptance gates in the 1.0.0 ledger, not completed by this first broker.

Tests must cover empty configuration and cancel preserving the conversation; connection cancellation/late reply; no network from validation or install alone; no call before explicit review; stale/expired/edited/duplicate review rejection; write-ahead log failure; no replay after interrupted/uncertain call; secret opt-in separation; bounded/corrupt metadata and log recovery; remote output not triggering another action. Native tests use an injected wire/client boundary only for deterministic failures, and real UIKit controls for acceptance. Actual user-approved server interoperability is a separately named blocker until supplied.
